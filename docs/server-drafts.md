# Доступ home.pl и серверные черновики

Установлено и проверено 17 октября 2026. Главный сайт и DNS не изменялись. Закрытый сервис использует имеющийся PHP-хостинг home.pl.

## Терминал

Из корня проекта:

```sh
tools/homepl-ssh.sh 'pwd'
tools/homepl-sftp.sh
```

SSH: `serwer2454127.home.pl`, порт **22222**, пользователь `serwer2454127`. Настройки изолированы от глобального SSH-конфига: `.server-access/ssh_config`. Проверка ключа сервера обязательна, пароли SSH отключены, forwarding запрещён. Ключ RSA 4096 зашифрован; пароль хранится в macOS Keychain под сервисом `AtlantAuto-homepl-SSH`, account `serwer2454127`. Приватный ключ, конфиг и known_hosts находятся в игнорируемой `.server-access/` (0700); приватный ключ 0600. Ключ сервера первоначально подтверждён одноразовым секретом через уже проверенный FTPS и чтением того же секрета через SSH. Старые authorized_keys сохранены, ключ добавлен без их удаления. FTP-пароль для последующих подключений не нужен.

Wrapper `homepl-sftp.sh` разрешает Keychain askpass и в пакетном режиме:

```sh
tools/homepl-sftp.sh -b - <<'EOF'
ls public_html/drafts
EOF
```

Это постоянная настройка повторного подключения, а не бесконечный SSH-сеанс. home.pl ограничивает длительность сессий. Сервис пока не поддерживает post-quantum SSH KEX; OpenSSH сообщает об этом. Проверка хоста, шифрование канала и современные RSA-подписи используются без ослабления проверок. Ключ владельца **не передавать коллеге**: SSH даёт доступ ко всему аккаунту хостинга. Для коллеги предназначен отдельный ключ приложения. Удаление соответствующей строки из `.ssh/authorized_keys` отзывает SSH-ключ; при смене компьютера нужна новая настройка ключа/Keychain.

## Просмотр и загрузка

- Закрытый интерфейс: https://serwer2454127.home.pl/drafts/ — обычная форма входа, логин `presentation`, существующий пароль просмотра презентации из локального `.presentation-access.json`. Пароль не передаётся в URL. HTTP Basic Auth для этого раздела заменена серверной сессией после ошибки ERR_INVALID_AUTH_CREDENTIALS во встроенном браузере.
- API: `https://serwer2454127.home.pl/internal-api/vehicle-drafts.php`; HTTPS, Bearer-ключ сотрудника, точный разрешённый extension origin. Origin — дополнительная проверка, **не замена ключу**: ID расширения не удостоверяет его неизменность.
- Расширение 0.3.0: «Сохранить черновик на сервере» сохраняет данные + все найденные фото Arval + выбранные вручную PDF. При отправке Telegram автоматически сохраняются данные + выбранные для альбома фото. Никакой автоматической публикации на сайте нет.
- PDF инспекции/PartsLink загружаются через поле файлов в расширении. VIN внутри PDF не распознаётся, соответствие проверяет сотрудник. Ссылки на отчёты хранятся, сами HTML-отчёты на сервер пока не копируются этим действием.
- Веб-интерфейс пока только для просмотра: поиск по VIN/модели/лоту, фото, документы, JSON, прежние снимки, история действий и текст Telegram. Файлы выдаются через авторизованный PHP-обработчик по случайному ID, PDF — attachment.

Настроены три независимых ключа: `owner`, `employee-2`, `employee-3`. Их локальные файлы находятся в игнорируемой `.server-access/employee-keys/` с правами 0600 (каталог 0700). `.telegram-employee-access.json` содержит копию ключа owner для совместимости с инструкцией установки. Прежний общий ключ colleague отозван; его резервная копия сохранена только локально. На сервере находятся только SHA-256-хэши действующих ключей. Проверены все три ключа в API хранилища и в проверке входных данных Telegram без отправки сообщений; старый ключ даёт 401.

В этой версии каждый сотрудник с ключом может читать **все** черновики и добавлять данные/файлы. Название ключа записывается как actor в новых событиях; исторические события colleague не переименовываются. Разделения по сотрудникам, удаления, редактирования состояния и админского SSH в расширении нет. Для другого сотрудника выдаётся новый ключ и отдельный хэш в конфигурации. Отзыв хэша отзывает доступ к API и Telegram; уже скачанные копии не удаляются. Не передавайте сотрудникам SSH-ключ или общий файл конфигурации бота; выдавайте только их отдельный файл employee-N.json.

## Где находятся данные

Web PHP работает в файловой изоляции home.pl и не видит FTP-каталог `/private`. Поэтому рабочие данные расположены в FTP `public_html/.atlant-internal/vehicle-drafts/`, закрытом HTTP-правилом `Require all denied` и правами 0700. Это **внутри web root с запретом выдачи**, а не физически вне web root. Проверено: прямые запросы к базе, конфигурации и служебной библиотеке дают 403. При переносе на другой сервер предпочтителен внешний приватный путь через `ATLANT_DRAFT_ROOT`.

Внутри: `drafts.sqlite` и неизменяемые объекты `objects/<draft-id>/<asset-id>` с правами 0600. SQLite хранит один черновик по VIN, исходные JSON-снимки, SHA-256 файлов, номера лотов, события и Telegram-подтверждения. Предыдущие снимки остаются, одинаковые файлы не дублируются. Повторный импорт старого снимка может восстановить его как текущий. Ссылки на источники не открываются сервером: нет произвольного скачивания URL или передачи cookie/паролей аукциона.

Ограничения первой версии: 2 МБ на JSON; 20 МБ на файл; 200 файлов / 250 МБ / 100 снимков на VIN; до 10 000 черновиков; 2 ГБ суммарно для файлов. JPEG/PNG/WebP проверяются по MIME и размерам, PDF — по MIME; PDF не анализируются и не сканируются на вредоносное содержимое. Любая неполная загрузка остаётся частичным черновиком. Веб-интерфейс показывает количество сохранённых файлов и ожидаемые фотографии; полного автоматического архивирования всех внешних отчётов пока нет.

API: `POST` JSON создаёт/обновляет VIN; `POST ?action=asset` принимает multipart `id, kind, source_url, file`; `GET ?q=…` список по 50 записей с `offset`; `GET ?id=…` детали; `GET ?asset=…` защищённый файл. Клиент не задаёт физический путь. Имя файла не используется как путь. POST не запускает торговых операций.

Telegram сохраняет `sending`, `sent`, `rejected` или `uncertain` в истории существующего VIN вместе с текстом и message IDs. Отдельное существующее idempotency-хранилище доставки предотвращает повтор альбома. Сбой истории не превращает доставленный альбом в ошибку повторной отправки: ответ содержит `history_saved`. Полная автономная повторная сборка/генерация сообщений из админки ещё не реализована. Сервер может хранить и выдавать уже загруженные файлы при выключенном компьютере; новые защищённые страницы Arval/PartsLink без сессии браузера не импортируются.

## Резервные копии

Установлен CLI-скрипт вне web root: `private/atlant-drafts-backup.php`. Он создаёт согласованную SQLite-копию, копирует неизменяемые объекты и проверяет SHA-256 каждого объекта и `PRAGMA integrity_check`.

```sh
tools/homepl-ssh.sh 'php private/atlant-drafts-backup.php'
```

Результат содержит путь `private/atlant-draft-backups/<время-id>`. Скачивание отдельной копии:

```sh
tools/homepl-sftp.sh
# В SFTP: get -r private/atlant-draft-backups/<время-id> _backups/
```

Первая копия с шестью проверенными файлами создана на сервере и скачана локально в `_backups/server-drafts-20261017/`. Автоматическое расписание, удалённая независимая резервная площадка и политика удаления/сроков хранения **пока не настроены**. Для начала регулярного использования нужно определить их отдельно. Скрипт не удаляет старые копии.

Восстановление: остановить запись в API, сохранить повреждённую текущую папку, загрузить проверенные `drafts.sqlite` и `objects` из одной копии, выставить 0700/0600, проверить SHA-256 и SQLite, открыть API. Секреты доступа не входят в эту копию данных; их восстановление отдельное. При несогласованности результата Telegram сначала проверить чат, не повторять отправку автоматически.

## Проверки

На сервере проверены HTTP/HTTPS, первоначальная Basic Auth (позже заменена формой), правильный и неправильный Bearer, CORS, закрытые внутренние файлы, загрузка пяти исходных фотографий BMW и тестового PDF, дедупликация, поиск по лоту, сохранность после нового запроса, скачивание с проверкой SHA-256, запрет поддельного изображения и path traversal, снимки и экранирование HTML. Демонстрационный черновик явно помечен как тестовый, без актуальной цены. Новых тестовых сообщений в Telegram при проверке хранилища не отправляли.

`tools/arval-capture.test.cjs` проверяет загрузку данных/обычных фото/повреждений/PDF в серверную API-модель, сохранение перед Telegram, отсутствие отправки при отдельном сохранении и отсутствие кликов/торговых запросов. Реальную установку 0.3.0 на компьютере коллеги ещё нужно выполнить; его авторизованная сессия в автоматических тестах не использовалась.

## Вход через форму

Для `/drafts/` применяется HTML-форма `/drafts/login.php`, без HTTP Basic challenge. Прежний bcrypt-хэш пользователя presentation читается из защищённого `/presentation/.htpasswd`; пароль не дублируется и не менялся. Сам раздел презентации сохраняет прежнюю Basic Auth.

Сессии находятся в закрытой `.atlant-internal/draft-sessions/`; cookie `__Secure-atlant_drafts` имеет Secure, HttpOnly, SameSite=Lax, host-only и path=/drafts/. Идентификатор меняется при входе. Лимит бездействия 30 минут, абсолютный срок 8 часов; смена хэша пароля отзывает существующие сессии. Вход и выход требуют CSRF-токен; после 8 неудачных проверок пароля с одного IP вход ограничивается на 15 минут. Используется REMOTE_ADDR, пользовательские proxy-заголовки не считаются доверенными. Перенаправление после входа допускает только локальные адреса раздела. Все выдачи файлов и JSON проходят ту же проверку сессии. Ключ API расширения остаётся независимым от браузерной сессии.

Исходники: `api/draft-viewer-auth.php` (внутренняя библиотека), `api/drafts-login.php` (на сервере drafts/login.php), `api/drafts-portal.php` (drafts/index.php). Предыдущие index.php и .htaccess сохранены в `.server-access/` для отката. При откате возвращаются согласованно оба файла. Проверены реальный вход с прежним паролем, ошибочный пароль, CSRF, смена ID сессии, защита фото, выход, запрет внешнего redirect и сохранность авторизации API расширения.

## Проверка подключения расширения · 0.4.2

`GET /internal-api/vehicle-drafts.php?action=identity` после обычной проверки HTTPS/CORS/Bearer возвращает только `{ok:true,employee:…}`, без доступа к базе и без выдачи списка машин. Расширение использует его после локального сохранения ключа; результат отображается непосредственно в блоке подключения сотрудника. Прежние API-действия и разрешения не менялись. Предыдущий обработчик сохранения показывал подтверждение в скрытом Telegram-разделе; это исправлено. Клиент различает сохранение в Chrome и подтверждение доступа сервером.

## Название автомобиля · 0.4.3

Расширение сохраняет исходное vehicle.title и отдельное display_title для публикации. Сервер использует display_title как заголовок черновика и будущей карточки кнопок, но исходные JSON-снимки не теряются. Для старых клиентов без display_title используется исходное название с устранением повторной марки. Полная каталожная база не подключена: есть правила Kia Sportage и консервативная очистка технических суффиксов для остальных моделей. Ручное исправление сохраняется как title_override. Старые опубликованные снимки не переименовываются автоматически.
