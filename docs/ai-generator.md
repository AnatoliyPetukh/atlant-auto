# Vehicle description and translation worker

ERP section: `Описание и переводы` (`section=generator`). Generation produces a separately stored review draft; it never edits or publishes a vehicle, changes status or sends Telegram messages. Staff must select PDF sources, consent to transmission to OpenAI and authenticate with their employee key. Default document selection is empty. Only same-VIN asset records categorized as inspection/PartsLink PDFs are eligible (up to 6 files, 20 MiB total). Original PDFs can contain personal details; staff must check them before authorizing transmission. Invoice, transport, registration, internal notes, account credentials and photos are not included. Structured source data uses an allowlist, removes URLs/contacts, and has a size limit. This does not redact originals inside selected PDFs.

Server configuration: `.atlant-internal/ai-generator.json`, chmod 0600, excluded from Git. Local owner staging: `.server-access/ai-generator.json`. Fields: enabled, api_key, model, daily_job_limit (default 20, max 100), max_output_tokens (default 5000, max 6000). API credentials are never returned to the UI. Current initial model: gpt-4.1-mini. API usage is billed separately from ChatGPT. Job counts/output limits are local guards, not a monetary cap; set project billing notifications separately.

Native home.pl scheduling: install `tools/homepl-cron-5min.php` as `public_html/cron-5min.php`, mode 0600, and `tools/homepl-ai-worker.php` as `.atlant-internal/ai-worker.php`, mode 0600. CLI only; HTTP returns 403. Provider runs every five minutes independently of the owner workstation. Worker uses a process lock, claims one job per run and a 100-second HTTPS timeout. `.atlant-internal/ai-worker-status.json` records the latest run. PHP native SQLite/cURL required. No external scheduler, shell browser or local computer daemon.

Jobs live in the existing SQLite database. Source snapshot, selected PDF IDs/digests, actor, model, prompt version, result, safe error and token usage persist. A duplicate input reuses its queued/running/completed job. Source change before processing rejects the job without calling the API. Changed source after generation blocks import into the editor. Unknown completion after a network interruption is marked uncertain, with no automatic retry. Interrupted running jobs become uncertain after ten minutes. A manual retry is a fresh paid attempt and consumes the daily job limit. Non-2xx errors do not log response bodies or keys.

The fixed worker calls only OpenAI Responses HTTPS, without tools/redirects, with strict JSON schema and `store:false`. Do not describe this as zero retention: provider abuse-monitoring policies may still apply. No publicly accessible PDF URLs or persistent OpenAI file uploads are used; selected bytes are inline file inputs. Source text/PDF instructions are untrusted. Prompt demands evidence references, unknowns, original vs first-registration date distinction, VIN conflict handling and damage severity/type rather than counts. Generated claims still need human verification.

The result includes Polish/Russian description, condition, maintenance, equipment, checks and evidence IDs. “Перенести польский текст в форму карточки” fills the website form without saving; explicit owner save updates an already published vehicle. Original source and prior text remain in snapshots/version history. Russian results can be reviewed/copied for Telegram; automatic replacement of the Telegram template is not implemented.

Verification: `php tools/ai-generator.test.php "$PWD/api/ai-store.php"` uses an isolated temporary SQLite database and mock transport, no live API or vehicle publication. Covers consent, document isolation, minimal input, idempotency, source changes, evidence and uncertain requests. Real API and native scheduler must be independently checked after configuration.
